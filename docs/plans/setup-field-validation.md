# Setup field validation

> **Status:** ready-for-human, 2026-10-04. Steps 1 to 9 landed in code on 2026-10-04; the one step left is the Windows check of a report with every field at its limit, which needs Word.
> From: docs/research/setup-field-validation.md

## Understanding

Setup must save incomplete drafts, but refuse malformed nonblank values that changed and block entry to Findings until required details are complete. An unchanged stored value that breaks a rule saves, and is a Setup issue until fixed. Web and API scope lines stay free text with no format check, and stored target text never changes. Network Access starts unselected on new drafts; old stored choices remain choices. Account pairing and duplicates are gate issues, while blank rows remain editable and disappear only from the Word User Roles table. Removing a tested environment clears its dates after confirmation, in the same undo action. Test dates are not compared with Report Date.

## Answers

Round 1, answered 2026-10-04.

- **Q1, length counting.** Both sides count UTF-16 code units, matching the browser's `maxlength`. An emoji counts as 2.
- **Q2, host path without a scheme.** Accepted at first, then made moot in round 2: scope lines get no format check at all.
- **Q3, hostnames.** Answered, then made moot in round 2 for the same reason.
- **Q4, values that break a new rule.** A save refuses only values that changed. An unchanged stored value that breaks a rule, such as one from an import (imports skip acceptance), saves and is a Setup issue until fixed.
- **Q5, CI and BSN.** Letters, digits and hyphens, at most 30, no spaces: today's character rule.

Round 2, answered 2026-10-04.

- **Scope format.** Web and API scope lines are not restricted, because testers enter too many kinds of scope to list. This withdraws the URL, hostname, IP, CIDR and host-path rules, and the round 2 questions about digit-only paths and old scope lines with them. It goes against the recommendation to check each line's format.
- **Glossary.** Scope target, Test account and Network access were added to `GLOSSARY.md`.
- **Word cover.** The template edit that makes the cover print Network Access is a separate work item: `.scratch/network-access-on-word-cover/`.

Network Access: this plan supersedes answer Q2 of `docs/plans/setup-network-access.md`, which chose the `Internal` default. The user now wants an explicit choice.

Round 3, answered 2026-10-04.

- **Q1, checks left on scope inputs.** Keep the length limits (500 per Web/API line, 200 per component, 500 per description). Drop the `component_scope` character rule. Every scope input refuses only characters Word cannot store: U+0000 to U+0008, U+000B, U+000C, U+000E to U+001F, U+FFFE, U+FFFF and unpaired surrogates (the XML 1.0 `Char` production). python-docx was checked: it accepts a tab and refuses U+0007, U+000B and U+FFFE, so one such character would abort generation. Web/API lines have that gap today.
- **Q2, the repo rule about `data/`.** Changed for every machine: `CLAUDE.md`, `.github/copilot-instructions.md` and both copies of the `invader` agent now call `data/` test drafts, say to base no decision on their contents, and to change or delete them only when the user asks. This goes against the recommendation to keep the committed rule and add a local note.

The research already settled the field policies and numeric limits. Do not reopen Network Access, account pairing, the environment-date behavior, Report Date ordering, or the free-text scope decision.

## Data risks

| Failure mode | Assessment |
| --- | --- |
| Stale write | **RISK.** Every full PUT must retain `saved_at` in the body. Keep the early 409 and locked compare, including a conflict after a failed validation or an attempted recovery. Do not auto-retry a 422 as a 409 overwrite. |
| Lost update | **clear if unchanged.** `acceptance.check` and `Workspace.save_if_current` already govern the write. Add no separate read/repair/write outside `Workspace._locked`. |
| Orphan reference | **RISK.** Scope validation must not canonicalize `ScopeTarget.value` or remint its ID; reconciliation must preserve referenced IDs and the existing removal confirmation. Account-row filtering occurs only in Word output, not in the saved draft. |
| Silent stranding | **RISK.** Removing a tested environment can remove the last location; retain the existing confirmation and target/evidence handling before clearing dates. Cancelling must leave dates and scope untouched. |
| Schema break | **RISK.** Existing stored `"Internal"` and `"External"` still validate. Missing network now reads as `None`, remains loadable and savable, and is a Findings gate issue. A Pydantic `max_length` on legacy fields would demote an overlong draft to the legacy list, so validate lengths at save instead. No `load_path` write or version bump is needed for this nullable widening; `schema_version` remains `1.4`. |
| Request/response asymmetry | **RISK.** `scope_text` is in Setup PUTs but not in responses. When it is absent, validate changed stored targets directly, including component descriptions; do not assume the normal Setup parser ran. Leave unchanged legacy targets savable, but surface invalid stored targets as Setup gate issues for repair. |
| Rule drift | **RISK.** Python and `rules.js` must return the same refusal/issue codes, order, row indices, length boundaries and control-character set. Update `DATA_MAP.md` section 12 and its shared case table together. |
| Navigation trap | **RISK.** `save()` only checks Setup inputs on Setup, while Back waits for a successful save and Undo can submit from any page. A new 422 may block Back on Findings/Content. Preserve the pending local draft and provide a path back to Setup to repair it without dropping unsaved Content; Next still checks completeness only at the gate. |
| Derived-state fight | **clear if unchanged.** `acceptance.provision` works on findings, not these engagement values; the browser must not replace `None` with `Internal` when it parses or reconciles a response. Do not strip or rewrite scope text to make it pass. |
| Backup exhaustion | **RISK.** Never repair nullable network or clear old windows of environments that are not tested in `load_path`: each rewrite consumes the single backup. Clearing dates after removing a tested environment must call `scheduleSave` once, not once per field. |

## What deviated

Step 8 stays unticked only for its Windows check: the Word output code and its tests landed, but a report with every field at its limit has not been generated with Word yet. The rest went as agreed, with these differences.

- **No HTML `maxlength`.** It cuts a pasted value short without saying so, which breaks "never truncate". Each field shows its length message and holds the save instead, and Add is disabled at 50 test accounts.
  - 2026-10-05: Ticket [03](../../.scratch/setup-inline-field-errors/issues/03-a-field-stops-at-its-character-limit.md) reverses this for eligible Setup inputs: `maxlength` stops typing, cuts pastes with a note, and leaves Web/API lines and component names uncapped.
- **The browser's Setup save still holds any field showing an error, an imported one included.** Only the server refuses changed values alone. On Setup the tester is already on the page that fixes the value.
- **Step 6 needed no new browser code.** Because the server refuses only changed values, an untouched Setup value can no longer fail a save from Findings or Content. Undo and local draft recovery are the remaining ways, as before. Step 6 added only the test that a stale save is a 409 even when it also breaks a Setup rule.
- **An editable DOCX import with a bad Setup value now imports.** It used to be refused; under answer Q4 the value becomes a Setup issue. A bad finding field still refuses the import.
- **A line or paragraph separator (U+2028, U+2029) in a component now passes.** Word can store it, so it is no longer refused; its test now checks that it stays inside one row.
- **`vrRules.usernameRefusal` became `vrRules.usernameRefusals`**, because a username can now earn two refusals, a space at an end and a length.
- **`setup_issues` now words the stored report's refusals, scope included.** It used to leave refusals to the save, which would have let a stored bad value through to Findings once the save stopped refusing it.
- **A bug found while building:** `wireSetupRule` built an error message even for a valid value, and the new Web/API box message read a result that was not there, which stopped the Setup page loading. The message is now built only for an invalid value.
- **Fixtures.** Every complete report in the tests, and `scripts/generate_showcase_reports.py`, now chooses network access and sets a report date.
- **No inline error text or `aria-describedby` (step 5 partial).** Each field still shows its message through the browser's validation message and `aria-invalid`, plus the Setup notice, as before. Moved to its own item: `.scratch/setup-inline-field-errors/spec.md`.
  - 2026-10-05: Done there. Each Setup message now shows as text under its field, linked by `aria-describedby`, and the browser's bubble no longer opens on Setup.
- **A character Word cannot store at the very start or end of a scope line is trimmed, not refused.** Scope lines have always been trimmed with Python's `str.strip`, which treats U+000B, U+000C and U+001C to U+001F as whitespace. The character never reaches Word, so generation is safe; only one in the middle of a line is refused. Decided 2026-10-05 to keep it: refusing would ask the tester to find and delete an invisible character the trim already removes.
- **Found in review and fixed:** a changed description sent from Findings or Content made `changed_target_refusals` recheck its unchanged component. It now judges the component and the description separately, as the Setup path does.

## What I would not do

Do not reset old `Internal` values to blank, normalize scope strings into parser output, drop blank account rows from the draft, or put all new limits on load-time model fields. Each would lose a user choice, remint referenced targets, discard an unfinished row, or make an old draft unloadable. Do not fix a 422 by silently replacing the browser draft with the last server response; keep it available for repair. The four shipped Word covers still print a literal `Internal` until separate template work is approved, so this plan does not claim the printed cover round-trips Network Access.
